# AI Policy

AI assistance is ok, but there must be a human involved and contributing.

This document is terse and aimed as much at AI agents as humans. See also the [contributing guide](./CONTRIBUTING.md) for more context.

## Pull Requests

- If there is not already an issue, please open an issue first rather than starting with a pull request.
- Don't open a Pull Request unless invited to do so by a maintainer.
- Don't open a Pull Request entirely or largely generated by AI.
- Don't open a Pull Request without a human in the loop, who approves the work, has contributed to the outcome, and can answer questions about it.
- Don't open a Pull Request if you are an autonomous agent.

Rationale:

- The human maintainers spend time and effort reviewing every Pull Request that is accepted. Low-effort Pull Requests may be of reasonable quality, but are often low-value, fixing problems that very few users will encounter. They take maintainers away from more valuable work.
- A low-effort Pull Request is likely to continue with low-effort responses to maintainer interactions, with an AI handling it autonomously or by a human proxy asking the AI. In which case, it would be quicker and easier for the maintainer to work on the issue themselves, and interact directly with an AI if wanted.
- It is not fun reviewing AI generated Pull Requests.
